# 도보권 지수 (Walkability Index)

대지 하나에서 목적지 하나까지 걸어서 닿는 정도를 0~100 의 절대 척도로 나타내는 지수를
정의하고, 위례신도시 55개 아파트 단지에 실제로 적용해 본 프로젝트다.

분양가를 산정할 때 지금은 감으로 매기는 입지 점수를 **재현 가능한 수치로 바꿔 보려는 시도**이며,
설계 논의의 전 과정은 **[`도보권지수_설계노트.md`](도보권지수_설계노트.md)** 에 서술형으로 기록되어 있다.
무엇이 확정되었고 무엇이 아직 열려 있는지, 그리고 중간에 어떤 판단이 틀렸고 왜 정정했는지까지
모두 남겨 두었으므로, 이 프로젝트를 이어받는다면 그 문서를 먼저 읽는 것이 좋다.

**현재 상태는 L2 완료**다. 감쇠함수를 확정했고, 위례신도시 단지를 수집했고,
T맵으로 실제 보행 경로까지 받아 지수를 산출했다. 다음 단계는 L3(유효거리 페널티)이다.

---

## 지수의 정의

```
WI(대지, 목적지) = S( d(대지, 목적지) )

S(d) = 100 / (1 + (d / d₀)^β)        d₀ = 1,000m,  β = 2.0
```

**단위는 "대지 하나와 목적지 하나가 이루는 한 쌍"** 이다.
여러 시설을 합산한 종합 점수는 지수의 정의에 포함하지 않는다.
도보권의 항목들은 서로 보상되지 않고(초등학교가 멀다는 것을 마트가 가깝다고 메꿀 수 없다),
가중치를 정당화할 방법이 없으며, 대상 가구에 따라 정답이 달라지기 때문이다.
종합이 필요하면 지수 바깥의 별도 레이어에서 만든다. (설계노트 2-1, 2-2절)

`d₀` 는 **지수가 50점이 되는 거리이자 곡선이 가장 가파른 구간을 결정하는 값**이고,
`β` 는 임계가 얼마나 날카로운지를 정한다.
`β` 는 전 시설 공통으로 고정하고 시설별로는 `d₀` 하나만 정하는데,
그래야 "50점"이 어느 시설에서나 같은 의미를 갖고 시설 간 비교가 성립한다. (설계노트 2-6절)

두 값 모두 **언제든 조정 가능한 손잡이**로 다루며, 노트북의 `WALK_PARAMS` 한 곳만 고치면
전체가 따라 바뀐다.

## 산출 결과 요약

위례신도시 55개 단지에서 **위례중앙역(미개통이므로 창곡동 506 건물로 가정)** 까지의 지수다.

| | L1 — 직선거리 | L2 — T맵 실경로 |
|---|---|---|
| 1위 | 위례센트럴자이 98.8 (109m) | 위례보미리즌빌 98.1 (138m) |
| 중앙값 | 69.0 | 54.3 |
| 최하위 | 위례포레자이 17.3 (2,189m) | 위례포레자이 10.2 (2,964m) |

**가장 중요한 발견은 L1 과 L2 의 순위가 크게 달랐다는 점이다.**
55개 중 50개의 순위가 바뀌었고 최대 변동은 10계단이며,
직선거리로 1위였던 위례센트럴자이가 실제 경로 기준으로는 10위로 밀렸다.

원인은 **단지 경계에서 실제 출입구까지 돌아나가는 고정 비용**이다.
이 비용은 거리가 짧을수록 비율로 크게 나타나므로 **역과 가까운 단지일수록 불리해지는
구조적 편향**이 생긴다. 실측 우회계수는 중앙값 1.356 이지만 개별 단지는 0.994~3.293 으로 벌어졌다.

따라서 **직선거리 기반 지수는 순위 비교에도 그대로 쓸 수 없다.** (설계노트 9-7절)

이 밖에 T맵의 소요시간이 사실상 거리의 선형 함수라는 점(상관 0.9994),
위례에는 계단·육교·지하보도가 하나도 없고 횡단보도만 경로당 평균 2.65회라는 점도 확인했다.

## 재현 방법

### 준비

저장소 루트의 `.env` 에 다음 키가 있어야 한다. **`.env` 는 커밋하지 않는다.**

```
KAKAO_REST_API_KEY=...     # 카카오 개발자 콘솔
VWORLD_API_KEY=...         # VWorld 오픈API
TMAP_APP_KEY=...           # SK open API (L2 에만 필요)
```

의존성은 저장소 루트의 `requirements.txt` 를 따르며, 여기에 더해 `numpy` 를 직접 사용한다.

### 실행 순서

`scripts/` 안의 스크립트는 **번호 순서대로 실행**하면 된다.
경로는 스크립트 위치를 기준으로 스스로 해결하므로 어디서 실행해도 무방하다.

| 스크립트 | 하는 일 |
|---|---|
| `01_아파트_탐색_반경2km.py` | 기준점 반경 2km 아파트 POI 수집 (초기 방식) |
| `02_단지정규화_필지수집.py` | 동 단위 POI 를 단지로 병합하고 VWorld 필지 경계 수집 |
| `03_지구경계_필터.py` | 위례 지구 경계를 받아 지구 안 단지만 선별 |
| `04_누락영역_보완.py` | 반경 2km 로 덮이지 않은 지구 외곽 보완 |
| `05_지구전역_재탐색.py` | **격자 200m × 반경 300m 로 지구 전역 완전 탐색** |
| `06_L1_도보권지수.py` | 대지 경계 직선거리 기준 지수 산출 |
| `07_TMAP_응답확인.py` | T맵 응답 구조 확인 (1건 테스트) |
| `08_L2_TMAP_실경로.py` | 55개 전수 실경로 수집 및 L2 지수 산출 |
| `09_L2_지도.py` | L2 기준 지도 생성 |
| `10~12_그래프_*.py` | 파라미터 검토용 그래프 |
| `20_노트북_빌더.py` | `도보권지수_분석.ipynb` 생성 |

01~04 는 **탐색 과정의 기록**이다. 처음부터 다시 만든다면 실제로는
지구 경계를 먼저 확보한 뒤 05 의 방식으로 한 번에 훑는 것이 맞다.

### 수집할 때 주의할 점

**카카오 키워드 검색은 한 번에 45건까지만 준다.** 아파트가 밀집한 지역에서는
반경 700m 로도 상한에 걸려 누락이 생긴다. 실제로 이 프로젝트에서 `래미안위례아파트` 가
그렇게 빠졌고, 격자를 200m 간격 · 반경 300m 로 촘촘하게 바꾸자 상한 도달이 0회가 되면서
3개 단지를 더 찾았다.

**각 검색이 상한에 걸렸는지를 반드시 기록해야 한다.**
상한 도달 횟수가 0이 되어야 비로소 완전 탐색이라고 말할 수 있다.

또한 **아파트는 카카오 카테고리 그룹 코드가 없으므로** 키워드 검색을 쓰고
`category_name` 이 `부동산 > 주거시설 > 아파트` 로 시작하는 것만 걸러야 한다.
그렇게 하지 않으면 아파트상가, 입출구, 주차장이 섞여 들어온다.

T맵은 일 1,000회 제한이 있다. 55개 단지 × 2회(옵션 0, 30) = 110회로 한도의 11% 다.

## 다음 단계 — L3

| 레벨 | 입력 거리 | 상태 |
|---|---|---|
| L1 | 대지 경계 직선거리 | 완료 |
| L2 | T맵 실경로 거리 | 완료 |
| **L3** | **유효거리 (횡단·계단·기피시설 페널티 반영)** | **다음** |
| L4 | 다시설 종합 | 지수 정의 바깥 (용도 레이어) |

L3 은 장애 요인을 전부 **거리로 환산해 하나의 축에 얹는** 방식이다.
8차선 횡단은 몇 미터짜리 불편인가를 정하고, 그만큼을 실제 거리에 더한 뒤 같은 감쇠함수에 넣는다.
지수 함수는 그대로 두고 입력만 바꾸므로 정의가 단순하게 유지되고,
계수를 나중에 실측이나 설문으로 교정할 수 있다.

다만 **위례에서는 계단·육교·지하보도를 검증할 수 없다.** 평지 신도시라 55개 경로 전체에
하나도 없었다. 횡단보도만 검증 가능하며, 계단 계수를 실측하려면
구릉지가 있는 지역에서 별도 표본을 잡아야 한다.

그 밖에 지하철역 외 시설(초등학교 등)의 `d₀` 를 정하는 일이 남아 있다.
제도상의 공식 수치, 실측 통행거리 분포의 중위값, 실무 감각의 세 가지 근거를 쓸 수 있으며,
자세한 내용은 설계노트 2-6절에 있다.
